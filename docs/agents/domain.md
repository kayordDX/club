# Domain docs

## Before domain exploration

Read root `GLOSSARY.md`, if present, and relevant decisions under
`docs/adr/`.

If these do not exist, proceed silently. Domain modeling creates
them lazily as terms and decisions are resolved.

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and
test names. Note meaningful vocabulary gaps for domain modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, identifying
the decision and why it may need reopening.
